# 长期要求与后续使用流程

本文件将本次用户要求保存为后续科研报告的默认约定。具体工作规则见项目 `AGENTS.md` 与 `skills/academic-paper-beamer/SKILL.md`。它们针对科研组会报告，不替代其他课程作业的格式要求。

## 用户已明确的要求

| 方面 | 长期要求 |
|---|---|
| 目标 | 不仅交付一份 PPT，还要形成以后可直接调用的专业流程 |
| 形式 | LaTeX 学术汇报；使用指定 RUC Beamer 主题，取消校徽背景水印 |
| 语言 | 中文为主，英文论文标题、术语、作者和必要内容保留英文 |
| 表达 | 专业、克制，减少模板化与 AI 式宣传表达；有自己的判断并与作者发现区分 |
| 时长 | 科研组会约半个多小时；通常 20 多到 30 页，必要时到 40 页 |
| 技术 | 页码、编号、结构、字体、公式、表格和插图均正确显示 |
| 方法 | 先从多个学术机构、专业文档和社区检索，整理有出处的 skill，再按它制作 |

## 后续一篇论文如何启动

可直接说明：

> 在本项目使用 $academic-paper-beamer，按长期要求处理这篇论文。PDF 在……。汇报约35分钟。

如用户改变模板、语言、时长或用途，以新要求覆盖相应默认值；不需要重新确认已明确的偏好。未给出报告人身份时不编造姓名或所属机构。

## 工作流及中间产物

1. **材料与版本。** 登记原始文件、下载地址、文件哈希、内部版本日期和出版信息；优先查最终稿及补充材料。确认是否真的是同一版本。
2. **研究阅读。** 从问题、机制、设计、估计对象、证据和边界逐层拆解；原文表图先于引言概括。
3. **证据登记。** 每个主要结论有物理页码、原文印刷页码和表图列号；原文错误或口径冲突单列。
4. **讲述组织。** 给出每页论点、证据、时间与过渡；先给核心问题及主要答案，再解释它如何被识别。
5. **LaTeX 实现。** 继承指定主题；沿用经检验的公式、三线表、分栏和插图模式。新论文放新目录。
6. **编译核查。** 至少两遍编译，检查字体、缺字、引用、编号、主附录计数和溢出；逐个复核数值。
7. **视觉核查。** 全部页面导出 PNG，检查每页的标题、正文、表图、脚注与页脚。修订后重新检查。
8. **演练与交付。** 本机排版检查与真实会场演练分开记录；交付放映 PDF、源码、讲稿、证据表和修改入口。

## 这次形成的知识工具

- 来源与取舍表：知道建议来自哪里、解决什么问题、哪些部分没有照搬。
- 科研报告 skill：把阅读、结构和实现连接起来，而非只有设计模板。
- 无水印主题与最小样例：以后可以先测试字体、公式、表格、图和编号。
- 编译脚本：统一生成并扫描日志。
- 验收脚本：检查 PDF、嵌入字体、边界、页码和源证据。
- 页级讲稿与提纲：用于调整时长、删页和回答问题。

## 不应被误当成“长期要求”的本次特殊情况

本次论文 SSRN 文件封面日期与网页更新时间不同，以及本机 CTeX 依赖冲突，属于已记录的当前事实，不应要求以后每篇论文都出现同样的问题。后续按实际材料重新核查。
